# 교회 재정 관리 — 홍보 랜딩 페이지 설계

작성일: 2026-06-06
프로젝트: `church-landing` (별도 레포, public)
소개 대상 제품: **교회 재정 관리** 안드로이드 앱 (`com.church.accounting`, Google Play 무료)

## 1. 목적 (Goals)

- 앱을 **소개**하고 **신뢰**를 주어 **Google Play 설치**로 연결한다.
- 오프라인 **A4 전단지의 QR**로 유입된 모바일 사용자가, 페이지를 보고 **고정된 설치 버튼**으로 Google Play에 도달하게 한다.
- 방문자가 원하면 **관심 등록 폼**으로 연락처를 남기고, 운영자가 그 내역을 확인한다.

### Non-Goals (이번 범위 아님)

- 라이선스 키 **구매/결제** 안내 (네이버 스마트스토어 등) — 일절 포함하지 않음.
- Windows 데스크톱 Pro 버전 소개 — 제외(안드로이드 앱만).
- 다국어 — 한국어만.

## 2. 대상 사용자

- 교회 **목사님**과 **회계 등 직분자**.
- **고령 사용자 다수** → 가독성·접근성(큰 글자, 고대비, 큰 터치영역)이 핵심.

## 3. 유입·전환 흐름

```
[A4 전단지: QR + 짧은 홍보문구]
   → (스마트폰 카메라로 QR 스캔)
[배포된 모바일 랜딩 페이지]
   → (화면 하단 고정 "설치하기" 버튼 탭)
[Google Play → 앱 설치]  (안드로이드 폰)
```

- 주 사용 맥락: **모바일(세로)**. 아이폰 Safari·데스크톱에서도 정상 표시.
- 앱은 **안드로이드 전용** → 아이폰 사용자는 소개만 보고, 설치는 안드로이드 폰에서 하도록 안내.

## 4. 전역 기능 (모든 화면 공통)

| 기능 | 동작 |
|---|---|
| **하단 고정 설치 바** | `📲 구글 플레이에서 설치하기` 버튼이 스크롤과 무관하게 항상 노출. 안드로이드 → Google Play로 이동. |
| **글자 크기 토글** | 상단에 `[보통] / [큰 글자]` 토글. 선택값 `localStorage` 저장(재방문 유지). 큰 글자 모드 = 본문/버튼/여백 확대. 기본값은 "보통". |
| **플랫폼 안내(iOS)** | iOS 감지 시 상단 배너 "아이폰에서는 소개만 보실 수 있어요. 설치는 안드로이드 폰에서 진행해 주세요." 설치 버튼을 눌러도 동일 안내 노출(이동 대신). 안드로이드는 바로 Play로 이동. |
| **접근성** | 고대비 색상, 최소 글자 크기 크게, 터치 타깃 ≥ 48px, 의미 있는 대체텍스트. |

## 5. 페이지 구성 (세로 스크롤, 단일 페이지)

1. **상단 바** — 앱 아이콘 + 앱 이름 / 우측 글자크기 토글
2. **(iOS) 안내 배너** — 안드로이드 전용 안내
3. **히어로** — 핵심 카피("교회 재정, 쉽고 투명하게") + 한 줄 부제 + 메인 화면 스크린샷 + `[설치하기]`
4. **누구를 위한 앱** — 목사님·회계 직분자 대상 + "설치 무료" 한 줄
5. **핵심 강점 4** — ① 쉽고 직관적 ② 한국 교회 특화 ③ 데이터 안전·투명 ④ 비용 부담 없음 (아이콘 + 짧은 설명)
6. **주요 기능(실제 스크린샷)** — 수입·지출 기록 / 결산 보고서 / 헌금영수증 / 성도 관리 / 백업·복원 (스크린샷 + 설명 교차 배치)
7. **3단계로 시작** — ① 설치 ② 교회·직분 설정 ③ 바로 기록
8. **데이터 안전** — 기기 내 저장(로컬) + 백업/복원 + 감사 기능
9. **관심 등록 폼** — §6
10. **FAQ** — "무료인가요?" / "아이폰도 되나요?" / "데이터는 어디 저장되나요?"
11. **마지막 설치 유도 + 푸터** — `[설치하기]` 재노출, 앱 정보·문의·패키지명

## 6. 관심 등록 폼 + 데이터 수집

### 입력 항목

| 필드 | 타입 | 필수 |
|---|---|---|
| 성명 | text | ✅ |
| 전화번호 | tel | ✅ |
| 직분 | select(목사/장로/권사/집사/회계/기타) + 기타 직접입력 | 선택 |
| 지역 | text | 선택 |
| 이메일 | email | 선택 |
| 개인정보 수집·이용 동의 | checkbox | ✅(필수 체크) |

- 제출 후: "등록되었습니다. 감사합니다 🙏" 노출, 폼 초기화.
- 동의 안내 문구: 수집 목적(앱 안내·문의 응대), 항목, 보관기간 간단 명시.

### 저장 — Supabase

- **정적 페이지 + Supabase JS 클라이언트**로 클라이언트에서 직접 INSERT (서버 불필요).
- **새 Supabase 프로젝트 1개** 생성(무료 슬롯 여유: 현재 `pixelmood-mvp` 1개만 사용 → 1자리 여유).
- 노출 키는 **anon(publishable) 키만** 사용. **service_role 키는 클라이언트/깃에 절대 미포함.**

#### 테이블 `landing_leads`

| 컬럼 | 타입 | 비고 |
|---|---|---|
| id | uuid (default gen_random_uuid) | PK |
| created_at | timestamptz (default now()) | 제출 시각 |
| name | text | 필수 |
| phone | text | 필수 |
| role | text | 선택 |
| region | text | 선택 |
| email | text | 선택 |
| consent | boolean | 동의 여부 |

#### RLS (Row Level Security)

- RLS **활성화**.
- 정책: **anon 역할은 INSERT만 허용**(`with check (consent = true)`), **SELECT/UPDATE/DELETE 불가**.
  → 공개 키로 저장만 가능, 다른 사람 제출 내용은 조회 불가(유출·스팸 수집 방지).
- 운영자 열람: Supabase 대시보드 Table Editor(또는 추후 service_role 기반 관리뷰).

#### 안티스팸(경량)

- 허니팟 숨김 필드(봇이 채우면 제출 무시). 과도한 캡차는 고령 사용자 배려로 도입하지 않음.

## 7. 비주얼 방향

- 교회 정서에 맞는 **따뜻하고 신뢰감 있는 톤** — 차분한 블루/그린 + 넉넉한 여백.
- **고대비 · 큰 글자 우선**(고령 가독성). 큰 글자 토글로 한 단계 더 확대.
- 실제 앱 스크린샷 사용(아래 §8). 정확한 폴리싱은 구현 단계(frontend-design)에서.

## 8. 자산 (기존 앱에서 재사용)

`church-accounting` 레포 `apps/android/public/`:

- 앱 아이콘: `icon-512x512.png`, `help/App_icon.png`
- 메인 화면: `help/Main.png`
- 기능 스크린샷: `help/Expense_records_*`, `help/Details_edit_*`, `help/closing_monthly_statement_report_*`, `help/closing_annual_Report_*`, `help/Donation_receipt_*`, `help/membership_*`, `help/setting_Data_Backup_*`, `help/setting_Data_recovery_*` 등
- 필요한 이미지는 `church-landing` 레포로 복사해 사용(원본 앱 레포는 수정하지 않음).

## 9. 기술 스택 · 구조

- **정적 단일 페이지**: HTML + Tailwind CSS + 바닐라 JS(토글/플랫폼감지/폼) + Supabase JS 클라이언트(CDN 또는 경량 번들).
- 빌드리스 우선. 필요 최소한의 자산(이미지, JS)만.
- 레포: `~/projects/church-landing` (별도 public 레포).
- `.gitignore`: `node_modules`, `.env*`, `.superpowers/`, OS 부산물. anon 키는 공개 가능하나, 키 분리를 위해 런타임 주입 또는 명시적 상수로 관리(service_role 절대 미포함).

## 10. 배포

- 정적 호스팅: **Vercel 또는 Netlify**(택1, 배포 시점 결정). 둘 다 무료.
- HTTPS 기본(카메라 QR→브라우저 접속에 필요).

## 11. 2단계 (배포 후 별도 산출물)

- 배포 URL 확정 → 그 URL로 **QR 코드 생성**.
- **A4 인쇄용 전단지** 디자인: QR + 짧은 홍보 문구(교회 게시판·주보 삽지용).

## 12. 결정 사항 요약

- 목적: 소개+신뢰+설치, **구매 미언급**.
- 대상: 목사·직분자, 고령 다수.
- 모바일 우선 + iOS 표시(설치는 안드로이드 안내).
- 글자크기 2단계 토글, 하단 고정 설치 바.
- 강점 4가지 모두 강조.
- 관심 등록 폼(성명·전화 필수 / 직분·지역·이메일 선택 / 동의 필수) → Supabase insert-only RLS.
- 정적 HTML + Tailwind + Supabase JS.

## 13. 미결/후속 (구현 계획에서 확정)

- 배포처 Vercel vs Netlify 최종 택1.
- 문의처(카카오톡 ID 등) 푸터 포함 여부 — 운영자 정보 확인 필요.
- 동의 안내 문구의 보관기간 등 구체 문구.
- Supabase anon 키 런타임 주입 방식(정적 호스팅 환경변수 또는 상수).
